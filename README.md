# Table Duel

iPad をテーブルに置き、画面の上下から 2 人が同時に操作して遊ぶ対戦ゲーム集 (PWA)。1 人で画面全体を使って遊ぶゲームも入っている。

https://oekazuma.github.io/table-duel/

## 遊び方

トップ (`/`) がゲームの一覧で、「ひとりで あそぶ」と「ふたりで あそぶ」に分かれている。遊びたいゲームを選ぶと、そのゲームのタイトル画面になる。

1 人用のゲームは画面全体を使い、「タップで スタート」で始まる。レベルを順にクリアしていき、どこまで進んだかはゲームごとに端末へ保存される。タイトルの ◀ ▶ で、たどり着いたレベルまでの好きな面を選び直せる。どのゲームもレベルは 100 まであり、100 面すべて違う面で、レベルが上がるほど難しくなる。100 をクリアすると「ぜんぶクリア！」。遊んでいる途中でも左上の ✕ でタイトルに戻れる。

2 人用のゲームは、iPad を 2 人の間に置き、両方のプレイヤーが自分側の画面を長押しするとゲームが始まる。iPad が横向き (回転ロック中を含む) のときは、ゲーム画面だけ 90 度回して縦長に使うので、2 人は画面の短い辺に向かい合って座る。手前が**プレイヤー 1**、向かいが**プレイヤー 2**。画面の上半分は 180 度回転しているので、どちらからでも読める。タイトル画面と結果画面の左端の ✕ で一覧に戻る。

Safari の共有メニューから「ホーム画面に追加」するとフルスクリーンで起動し、オフラインでも動く。

新しいバージョンが公開されると、一覧の上に「最新版に更新」ボタンが出る。押すとオフライン用の保存を取り込み直してから読み直す。いまのバージョン (ビルド時刻と git の短いハッシュ) もそこに出ている。

## 収録ゲーム

### ピンぬき (pin-rescue)・1 人用

ピンを抜く順番を考えて、金貨を男の子に届けるパズル。

- ピンはタップで抜ける。金貨と宝石・マグマ・水は粒になって流れ落ちる。届いた金貨は左上の金額に足されていく
- 男の子のいる床に、決まった割合の金貨が届けばクリア。マグマに触れるとしっぱい
- 水がマグマに触れると石になり、石に触れたマグマも冷えて固まる
- 仕掛けの型は 8 つで、レベルが上がると次の型に進む (1 本 → 選ぶ → 2 段 → 水 → 落とし穴 → 水で固めてから → 抜いてはいけないピン → ぜんぶ入り)。同じ型のあいだも、左右の向き・位置・金やマグマの量が面ごとに変わり、要る金の割合 (5 割 → 7 割半) が少しずつ上がる
- 100 面すべて、用意した抜き順でクリアできることと、わなのある面は考えずに全部抜くと失敗することを、テストで確かめている
- 右上の ↻ で面をやり直せる

### 数のゲート (gate-run)・1 人用

仲間の群れを率いて走り、門で数をふやして最後に敵の城をたおす。

- 群れは自動で前へ進む。画面のどこかに指を置いて左右に動かすと、群れも左右に動く
- 青い門 (+・×) をくぐると仲間がふえ、赤い門 (-・÷) だと減る
- 途中の敵の群れとぶつかると、止まって同じ数ずつ減らし合う。仲間がいなくなるとしっぱい
- 最後の城の数より多く残っていればクリア。コースはレベルごとに決まっていて、門ごとに多くなるほうを選べば必ずクリアできる (100 面ともテストで確かめている)。最初の 2 面は増える門しか出ない。レベルが上がるほどコースが長く、敵の群れと減らす門が増え、城が強くなる

### 線を引いて守る (dog-guard)・1 人用

指で 1 本だけ線をかいて、巣から飛んでくるハチから犬を守る。

- 指を置いて動かすと線がかける。インクには限りがあり、犬のすぐまわりと雲の中にはかけない
- 指を離すと線が固まり、ハチが出てくる。ハチはいちばん近い犬をめがけて飛び、線や足場に当たるとはね返る
- 決まった時間を守りきればクリア。1 匹でも犬に届くとしっぱい
- 面はレベルごとに組み立てる。仕掛けの型 (ひらけた場所・洞窟の穴だけふさぐ・雲の下の横穴・宙に浮いた足場・2 ひきの犬・洞窟 2 つ など) はレベルが上がるにつれて増え、位置や大きさは面ごとに変わる。線を引く前にその面のひとことが出る
- レベルが上がるほど、ハチが増えて速くなり、巣が増え、守る時間がのび、速いハチ (オレンジ)・大きいハチが混ざり、インクのゆとりが減る
- 100 面すべて、用意した線でクリアできることと、線がなければ刺されることを、テストで確かめている

### 雪原サバイバル (snow-camp)・1 人用

雪原で動物をたおしてお肉を集め、キャンプでお金をかせいで家を建てる。

- 画面のどこかに指を置いてずらすと、その向きへ歩く (仮想スティック)
- 動物に近づくと、斧を振って自動で攻撃する。ウサギは 1 回でたおせて肉 1 つ、クマは何回か当てると肉 3 つ。ウサギは近づくと逃げる
- 肉は歩いて拾う (持てる数に限りがある)。たき火に近づくと渡して焼き、焼けた料理を並んでいる人が食べてお金を置いていく
- 置かれたお金は歩いて拾う。青いパッドに乗るとお金を払って「もてる数」「つよさ」「やく早さ」が上がる
- 金色の家のパッドにお金を払いきったらクリア。レベルが上がるほど、家とパッドが高くなり、クマが増えて固くなり、ウサギの逃げ足が速くなり、焼くのに時間がかかる。狩り場の木の並びは面ごとに違う
- 画面の上に「いまやること」が出て、行き先には黄色い目印、主人公の足もとには行き先を指す矢印が出る。たき火・おかね・各パッドには名札がある

### せめぎあい (border-rush)

画面中央の境界線が 2 人の陣地を分ける。自分の陣地に出る玉を消すと境界線が相手側へ押し込まれ、相手の端まで押し切ったら勝ち。

| 玉               | 操作                                             | 押し込む量 |
| ---------------- | ------------------------------------------------ | ---------- |
| 塗りつぶした丸   | タップ                                           | 小         |
| 二重の輪         | ゲージが溜まるまで長押し                         | 中         |
| 境界線上の金の丸 | どちらのプレイヤーでも取れる。先に触った方が取る | 大         |

境界線が動くと、相手側に取り残された玉は消える。負けている側は陣地が狭いぶん玉が密集するため、連打で押し返しやすい。

### ばくだんリレー (bomb-relay)

導火線の見えない爆弾を押しつけ合う。爆弾は必ずどちらかの陣地で爆発する。

- 自分の陣地にある爆弾は、指を置いてつかむ。飛んでくる途中でも、通り道に置いた指で受け止められる
- 持っているあいだだけ自分のメーターがたまり、満タンで勝ち
- 爆発した側はメーターが半分になり、次の爆弾はその側へ落ちる
- スワイプの勢いではじいて相手の陣地へ渡す。弱いと自分の陣地に残る
- 古い爆弾ほど赤く速く脈打ち、音も速くなる。そのぶんメーターも速くたまるので、危ない爆弾ほど持っていたくなる

### ホッケー (hockey)

自分の陣地に置いた指が、そのままマレットになる。

- マレットは 1 人 1 本。先に置いた指だけがマレットになり、ほかの指は無視する。その指を離せば、同じ陣地に残っている次の指がマレットになる
- マレットは自分の陣地から出られない。パックは左右の壁で跳ね、相手の辺の中央のゴールに入れば 1 点。5 点先取
- 失点した側の陣地にパックが置かれ、少し点滅してから再開する

### フィッシュプル (fish-pull)

池の真ん中の魚を、2 人で釣り糸を引いて取り合う。

- 自分の陣地で指を手前へ引くと糸をたぐる。2 本の指で交互に引けば速い
- 引くほど自分の糸が張る (手元のバーが緑から赤へ)。いっぱいになると切れて 1.5 秒引けず、魚は相手側へ逃げる
- 魚はときどき暴れる。暴れているあいだは糸がすぐ張るので、手を緩めないと切れる
- 魚を自分の手前の網の線まで引き寄せたら勝ち

### 虫送り (bug-rush)

真ん中の巣から湧き続ける虫を、相手の陣地へはじき飛ばし合う。

- 自分の陣地の虫をタップすると、相手の陣地へ飛んでいく
- 茶色のカブトムシは 3 回タップしないと飛ばず、3 匹ぶんに数える
- 30 秒たった時点で、自分の陣地の虫が少ないほうが勝ち。同じ数なら差がつくまで延長

### ライトニング (lightning)

合図と同時に出る指示に、相手より早く正しく応える。

- 指示はタップ・長押し・2 本指タップ・スワイプ (上下左右は自分から見た向き) のどれか。先に正しく応えたほうが 1 点
- 違う操作をするとその指示には応えられない。合図の前に触るとおてつき
- ドクロが出たら触ってはいけない。触ると相手の点
- 先に 5 点取ったら勝ち

### シールドブレイク (shield-break)

拍に合わせて 2 人が同時に行動を出し、読み合う。

- 真ん中の輪が縮みきった瞬間に、2 人の行動をくらべる。拍はだんだん速くなる
- タップでエネルギーをためる (最大 3)。相手へ向けてスワイプすると、エネルギーを 1 使って攻撃
- 拍の瞬間に指を置いていればガード。攻撃を受け止めるたびに盾が 1 つ減り、尽きると防げない
- 攻撃どうしは相打ちで消える。相手の体力 3 を先に削りきったら勝ち

### フェイントマスター (feint-master)

押していい合図の条件を、2 人が半分ずつしか知らない。

- 回のはじめに、自分の手元へ「いろ」か「かたち」のどちらか片方だけが出る (相手はもう片方)。すぐ消えるので覚える
- 真ん中の合図が次々に切り替わる。色も形も合った合図で先に押せば 1 点、違う合図で押すとおてつきで相手の 1 点
- 自分の半分が合っても、もう半分は分からない。相手が押しに行くかを読むか、押すふりで相手を釣る
- 先に 3 点取ったら勝ち

## ゲームを追加する

1 本のゲームは `src/lib/games/<id>/` に閉じる。既存のゲームのコードには触らない。

1. 対戦本体のコンポーネントを置く。勝者が決まったら `onfinish(1 | 2)` を 1 回呼ぶ (1 が手前、2 が向かい)。1 人用なら `SoloProps` を受け、`level` (1 から) に合った面を遊ばせて、クリアかしっぱいが決まったら `onfinish(true | false)` を 1 回呼ぶ

   ```svelte
   <script lang="ts">
     import type { GameProps } from '$lib/games';

     let { onfinish }: GameProps = $props();
   </script>
   ```

2. タイトル画面に上下それぞれ出す遊び方を `Howto.svelte` に書く。1 行のルールと凡例くらいに留める
3. 一覧のカードに出す小さな絵を `Thumb.svelte` に書く。一覧に全ゲームぶん載るので、軽い CSS だけで描く（画像・canvas・three は使わない）
4. `meta.ts` に一覧用の情報と読み込み方を書く

   ```ts
   import type { GameMeta } from '$lib/games';
   import Thumb from './Thumb.svelte';

   export default {
     id: 'my-game', // URL (/games/my-game) になるので kebab-case
     name: '表示名',
     description: '一覧のカードに出す 1 文',
     players: 2, // 1 人用は 1
     minutes: '1分',
     Thumb,
     load: async () => ({
       Game: (await import('./MyGame.svelte')).default,
       Howto: (await import('./Howto.svelte')).default
     })
   } satisfies GameMeta;
   ```

5. `src/lib/games.ts` の `games` 配列に 1 行足す

一覧のカードと `/games/<id>` のページはこれだけでできる (プリレンダーの対象も `games` 配列から作る)。ゲーム本体は遊ぶときに読み込むので、ゲームを増やしても一覧画面は重くならない。

タイトル画面 (両者の長押しでスタート)・結果画面・再戦・一覧へ戻る・ミュートは `src/lib/components/GameShell.svelte` が全ゲームぶん持つ。1 人用は `SoloShell.svelte` が、タイトル・結果・レベルの保存を持つ。上下 2 分割のレイアウト (`.stage` / `.half`) は `src/app.css` の共通クラス。

ゲームのルールは DOM に依存しない純粋なモジュールに分け (各ゲームの `engine.ts`)、コンポーネントは描画と Pointer Events の処理だけを担当する。盤面上の指の追跡は `src/lib/board-input.ts`、`requestAnimationFrame` のループは `src/lib/loop.ts`、得点の丸表示は `src/lib/components/Pips.svelte` を使える。コンポーネントは 200 行未満に保つ (`architecture/component-size`)。

## 開発

```bash
pnpm install
pnpm dev        # http://localhost:5173/table-duel/
```

| コマンド       | 内容                                                                    |
| -------------- | ----------------------------------------------------------------------- |
| `pnpm dev`     | 開発サーバー                                                            |
| `pnpm build`   | 静的ビルド (`build/`)。`BASE_PATH` でサブパスを指定する                 |
| `pnpm preview` | ビルド結果の確認 (Service Worker はビルドでのみ有効)                    |
| `pnpm lint`    | prettier / eslint / markuplint                                          |
| `pnpm format`  | prettier --write                                                        |
| `pnpm check`   | svelte-check と scripts の型チェック                                    |
| `pnpm test`    | vitest の watch。`pnpm test:run` で一括実行                             |
| `pnpm vitals`  | svelte-vitals の全体スキャン                                            |
| `pnpm verify`  | lint / check / test:run / vitals / build をまとめて実行 (CI と同じ判定) |
| `pnpm icon`    | `static/icon-*.png` を再生成する                                        |

依存は `pnpm-workspace.yaml` の catalog で一元管理し、Renovate が minor/patch を自動マージする。

サブパス配下で配信するため、アセットは `$app/paths` 経由か `%sveltekit.assets%` で参照する。絶対パスを直書きすると 404 になる。GitHub Pages はヘッダを出せないので、CSP は `<meta http-equiv>` で配る (`vite.config.ts`)。

## 公開

`main` への push で GitHub Actions がビルドし、GitHub Pages へデプロイする (`BASE_PATH=/<リポジトリ名>`)。公開先を変えるときは `BASE_PATH=/other pnpm build` のように base を変えるだけでよい。`static/manifest.webmanifest` の `start_url` と `scope` は相対パス (`./`) なので `BASE_PATH` に自動で追従する。絶対パスにはしない。
